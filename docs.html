Developer Quickstart

Nexilo enables permissionless AI inference with zero accounts, zero proprietary API keys, and atomic pay-per-token settlement in USDT via HTTP 402.

1. Installation

Install the official Nexilo client library using pip or npm:

Python Node.js / Bun 
pip install nexilo-ai

2. Authentication & x402

Nexilo has no accounts and no API keys to leak. Every request is authorized at the HTTP layer using the x402 payment standard: the orchestrator replies with a 402 Payment Required challenge, your client answers with a signed EIP-712 authorization from your own wallet, and the stream begins. The signature proves budget, never identity.

challenge / response headers 
HTTP/1.1 402 Payment Required
X-Payment-Required: eip712
X-Price: 0.0000008 USDT/token
X-Ceiling-Max: 2.00 USDT

# Client answers with a wallet signature
HTTP/1.1 200 OK
X-Payment-Signature: 0xf3a9...
X-Session-Channel: ws://mesh.nexilo.network/s/9c12

3. Spending Ceilings

A spending ceiling is the hard safety limit attached to every request. Your client signs the ceiling before a single token is generated, so a malformed loop, a hostile prompt, or a stalled node can never charge you more than the amount you authorized. Unstreamed tokens are never settled.

  • Per request: capped at $2.00 USDT by default, configurable down to $0.01.
  • Per session: a rolling session budget across many prompts, signed once.
  • Failure behavior: if the ceiling is reached mid-stream, the connection closes and you settle only for tokens already delivered.

4. Streaming Inference (Python)

No signups or centralized API keys needed. You only supply a wallet private key that authorizes the micro-payment ceiling for the request.

stream_inference.py 
import asyncio
from nexilo import AsyncNexiloClient

async def main():
    # Initialize client with your Web3 wallet
    client = AsyncNexiloClient(
        wallet_private_key="0x...", # Signs x402 spending ceiling
        max_ceiling_usdt=2.00       # Hard safety limit per request
    )

    # Stream output from the decentralized GPU network
    stream = await client.chat.completions.create(
        model="llama-3.3-70b-instruct",
        messages=[
            {"role": "system", "content": "You are a helpful coding assistant."},
            {"role": "user", "content": "Write a fast Python quicksort."}
        ],
        stream=True
    )

    async for chunk in stream:
        if chunk.delta.content:
            print(chunk.delta.content, end="", flush=True)

    # Automatically prints on-chain settlement receipt
    print(f"\n\nSettlement: {stream.settlement_tokens} tokens @ {stream.usdt_settled} USDT (All Networks)")

if __name__ == "__main__":
    asyncio.run(main())

5. Streaming Inference (TypeScript)

index.ts 
import { NexiloClient } from '@nexilo/sdk';

const client = new NexiloClient({
  privateKey: process.env.WALLET_PRIVATE_KEY!,
  maxCeilingUSDT: 2.00,
});

async function run() {
  const stream = await client.chat.stream({
    model: 'deepseek-v3-671b',
    messages: [{ role: 'user', content: 'Explain decentralized AI routing' }],
  });

  for await (const chunk of stream) {
    process.stdout.write(chunk.content);
  }

  const receipt = await stream.getReceipt();
  console.log(`\nVerified Tx (Multi-Chain): ${receipt.transactionHash}`);
}

run();

6. Raw HTTP / cURL

Prefer to stay in your shell? The x402 flow is just two HTTP round-trips, so it works out of the box with any language. Sign the ceiling with your key-deriving helper, replay the signature in the response header, and read the stream.

curl.sh 
# 1. Fire the request — server replies 402 with the price
CEILING=$(nexilo sign-ceiling --usdt 0.50 --wallet 0x...)

# 2. Replay the signature and stream tokens back
curl -N \
  -H "X-Payment-Signature: $CEILING" \
  -H "Content-Type: application/json" \
  https://api.nexilo.network/v1/chat/completions \
  -d '{"model":"llama-3.3-70b","stream":true,"messages":[{"role":"user","content":"Hi"}]}'

The -N flag disables buffering so you see tokens as they stream. When the response ends, the SDK auto-verifies the on-chain receipt and refunds the unused portion of your ceiling.

The x402 Protocol Specification

Nexilo standardizes on HTTP 402 Payment Required status headers:

How the 4 hops work:
  1. Hop 1: Client initiates request; Orchestrator replies with HTTP 402 challenge specifying token unit price and session channel.
  2. Hop 2: Client signs an EIP-712 spending ceiling authorization up to $2 USDT.
  3. Hop 3: Orchestrator selects lowest-latency GPU node and streams response tokens back over WebSocket.
  4. Hop 4: Stream terminates. Orchestrator submits signed delta proof to multi-chain contract; 90% goes directly to node operator.

Multi-Chain Settlement

Nexilo settles every inference stream atomically. The orchestrator batches token-delta proofs and posts them to whichever chain your operator set their payout wallet on — Ethereum, Arbitrum, Base, or any x402-compliant settlement layer. You never have to wrap, bridge, or worry about gas to call the API.

  • Prove & verify: each stream chunk is SHA-256 chained; the operator publishes the final digest on-chain.
  • Refund path: unused ceiling is returned to the payer the same block.
  • Operator yield: 90% of the token fee streams straight to the node operator's self-custodial wallet.

Orchestrator Mesh

A lightweight control plane picks the optimal node for each request in under 200 ms. Routing scores nodes by three signals: latency to your IP, current load on that exact model, and the operator's on-chain reputation. If a node drops mid-stream, the orchestrator re-hops the remaining prompt to a second node and settles only what was actually delivered.

Why it feels instant: the mesh pre-warms hot models across all regions, so a cold start happens at most once per node, not per request.

Running the Daemon

The operator is a single Go binary that manages model caching, serving, and settlement for you:

operator.sh 
# 1. Install the node daemon
curl -sSL https://node.nexilo.network/install.sh | sh

# 2. Point it at your payout wallet and enable it
nexilo-operator start \
  --payout-wallet 0xYourOperatorWallet \
  --models llama-3.3-70b,deepseek-v3-671b \
  --region eu-central-1

# 3. Watch earnings roll in
nexilo-operator tail --settlements

The daemon self-benchmarks on first boot and only advertises models it can serve within its SLO.

90% Payout Mechanics

Of every USDT micro-fee, 90% is routed directly to the operator. The remaining 10% funds the network: 6% is held in the slashing pool (security), 3% pays orchestrator routing, and 1% is minted into the liquidity pool that guarantees instant operator exits.

Slashing: a node that serves a corrupted stream (digest mismatch) has its 10% security bond slashed to the payer. One strike.
